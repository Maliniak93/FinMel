# The e2e part

Every epic whose change is visible in the app ends with a part labelled `e2e` (`create --e2e --parent <epic>`, tier 1, kind new, from `.claude/skills/design/e2e-part-template.md`, four fixed ACs, no `## Test manualny` of its own). An e2e coverage epic (tests for features that already exist) is instead a sequence of **own-plan** e2e parts, one per area, each with its own numbered `## Test manualny` and the own-plan variant of the template; the umbrella holds no plan and gets no trailing e2e part. `prepare` emits `workflowArgs.e2e` (and `ownPlan: true` for an e2e part whose body has a numbered `## Test manualny`; the workflow then automates that plan into the spec file its Goal names and refreshes `<n>.manual.md` for the part's own issue instead of the epic's), and for an e2e part whose branch has no commits ahead of `origin/master` it recuts the branch from `origin/master`. `build-feature.js` then runs **e2e → review** (no test-writer, no implementer): the `e2e` agent writes the tests from the epic's plan, refreshes it (`manualTest`), runs `verify.mjs --projects e2e` and the whole suite, and classifies every failure — test or harness code (fixed, up to 3 rounds), flaky (green, listed in the report), environment (blocked, class `environment`), stable app failure (blocked, class `app`, with the test, its `Krok <n>`, the trace and report paths and `blocked.selfCheck`). Before an `app` block the agent runs a **self-check**, once per failing test: it rewrites the failing assertion with `expectProjected` (`e2e/tests/projection.ts`, 30 s, re-fetches before every attempt) and reruns only that test with `e2e.mjs run --grep`; green means a test defect (the rewrite stays, one test-code round), red blocks as `app` and the block comment prints `- self-check: …`. A Reporting projection value is asserted with `expectProjected`; a `toPass`/`expect.poll` on it without a re-fetch is forbidden. The reviewer blocks an unmapped plan step, an assertion that differs from the plan, any changed file outside `e2e/`, a new `test.skip`/`test.fixme`/`waitForTimeout`, a new `toPass`/`expect.poll` on a projection value without a re-fetch and a weakened existing test. `ship.mjs` gates an e2e part on `verify.mjs --projects e2e --cache-check` plus `node scripts/e2e.mjs check` (a green, whole-suite `.git/e2e-result.json` with the fingerprint of the tree about to be committed); the report line is `**e2e:** <passed>/<total> green` plus the flaky tests. A block at stage `e2e` commits nothing: `ship.mjs --blocked` posts `**Blocked** at \`e2e\` (app|environment)`, saves the uncommitted diff to the gitignored `skarbiec-plan/issues/<n>.e2e.patch`, restores the tree and switches to `master`, so `/fix` starts clean. After the fix merges, `/build #<n>` (or `autobuild.mjs`) recuts the branch from master and the agent writes the tests again; the patch is for reference, except after an **E2E test defect** diagnosis (`autobuild.md`, "The e2e part in an unattended run"): then `prepare` applies it.
