# Resume replays finished steps

When `prepare` finds its issue branch already checked out with a dirty tree, `scripts/build-replay.mjs` reads the newest `build-feature` run of that issue from the Claude Code history (`projects/<repo path>/<session>/subagents/workflows/<run>/journal.jsonl`, plus the run record `workflows/<run>.json` once the run finished) and `prepare` writes a gitignored `skarbiec-plan/issues/<n>.resume.js` (the workflow with its `// @replay` line filled in); `/build` calls `Workflow` with that `scriptPath`, so `step()` returns each recorded result in order without an agent call and only the first unfinished step runs live (told that its partial changes are on disk). End rule: no record (interrupted), `ready` and a `budget` block replay every finished step; a block at `implement` or `review` replays all but the step that blocked; a block at `tests`, `input` or `e2e` replays nothing. A label that no longer matches, a changed tier/skip/e2e, a spec body that differs from the last run's, or `--fresh` falls back to a normal run. `<n>.run.json` (`bodyHash`, args, `replayed` steps, `writtenAt`) lets a run launched from a resume script, whose journal only holds its live steps, be prefixed with the steps its predecessor replayed. `node scripts/build-replay.mjs <issue> [--history <dir>]` shows what a resume would do.
